# Économiser l'abonnement de Kevin : mesurer ce qui coûte, couper à la source (Kevin 11.11.2026 : « apprendre de notre travail et de moi, ne pas trop consommer mon abo »)
- Mesure réelle (`node tools/memory/improve-system.mjs --travail`, 0 jeton, lecture locale) sur une session de 11.11 : 1 197 résultats d'outils = 3,1 millions de caractères (≈ 800 000 jetons relus). Postes : `Bash` 836 k · **`ReadNotifications` 813 k** · requêtes D1 du pont 318 k · `list_sessions` 178 k · recherches Gmail 168 k.
- **1. Les alertes de PR coûtent le plus** : chaque PR crée 3 à 6 alertes de ~10-20 k caractères (le même texte standard à chaque fois). Se désabonner (`unsubscribe_pr_activity`) NE les arrête PAS (mesuré 11.11 : les alertes continuent d'arriver) ; la seule vraie économie est d'ouvrir MOINS de PR : UN seul chantier = UNE seule PR (jamais une PR par petit correctif : regrouper tests + documents + correctif). On ne reste abonné qu'à une PR dont on attend vraiment la CI ou un relecteur.
- **2. Couper les sorties à la source** : `grep … | cut -c1-200 | head`, `gh api … --jq`, `git diff --stat`, jamais une ligne de `package.json` (`test:ci` fait 48 000 caractères) ni un journal entier ; lire un journal d'échec avec `grep -n "✗\|Error" | tail`.
- **3. Requêtes bornées** : `list_sessions` avec `limit` ≤ 10 ; D1 du pont `SELECT` de colonnes utiles + `LIMIT 20`, `WHERE id > <dernier lu>` ; Gmail `search_threads` avec une requête étroite ; ne jamais recharger une liste déjà lue.
- **4. Apprendre une fois** : une erreur vue 2 fois = on cherche la cause, on écrit le garde, on met UNE ligne en mémoire compacte (`improve-system.mjs --memoriser`, lignes génériques, aucune phrase de Kevin) ; au démarrage d'un sujet on rappelle 3-5 lignes (`mem.cjs search`), on ne relit pas les gros documents.
- Quand : à la demande de Kevin (« relis »), ou à la fin d'un gros chantier ; jamais en cron. Aucun modèle n'est appelé.
- Garde : `npm run test:improve-system` (rouge si le regroupement des erreurs ou le comptage des sorties lourdes casse).
